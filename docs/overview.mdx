AI agents are now first-class users of your software. They read your docs, call your APIs, and use your SDKs, CLIs, MCP servers, and skills. When an agent fails with your product, users churn. Deterministic tests check that your software behaves as expected, not that an agent reliably completes a task.

**reeval** is an open-source TypeScript evaluation harness, and your evals and results live alongside your code in git.

reeval tests agents the way they use your product. You write a [task](/reference/glossary#task): the prompt an agent gets, and the graders that check what it leaves behind. reeval runs real coding agents on the task, with each [trial](/reference/glossary#trial) in its own [sandbox](/reference/glossary#sandbox), and each [trajectory](/reference/glossary#trajectory) shows the step where an agent went wrong.

Install it and follow the [Quickstart](/getting-started/quickstart):

```bash
npm install -D reeval
```

Each run pinpoints where and why agents fail, so you can fix your product until agents succeed more reliably, in fewer steps, and at lower cost. The same evals catch regressions as your product and your agents change.

## How reeval works

You set up [agents](/reference/glossary#agent), [variants](/reference/glossary#variant) and [trials](/reference/glossary#trial), and reeval multiplies them into [sandboxes](/reference/glossary#sandbox): each trial of each agent on each variant runs in its own sandbox. [Graders](/reference/glossary#grader) read the workspace that each sandbox leaves behind. reeval then measures the results, compares them with the [baseline](/reference/glossary#baseline) and with [past runs](/reference/glossary#past-runs), and [analyzes](/reference/glossary#analysis) them.

[Graders](/reference/glossary#grader) check files and commands first, and a [model grader](/reference/glossary#model-grader) judges only what code can't. Each trajectory stays in the [results viewer](/results/inspection/studio).

The brand example in the [Quickstart](/getting-started/quickstart) prints a result like this:

```text
└─ · brand  mean 100% · 4/4 runs at 100% (pass@4)  capability(1)
     arm               pass
     page              0 of 4
       error  score 0.33 below 1: brand-orange scored 0.00; brand-fonts scored 0.00 (4 runs)
     brand-guidelines  4 of 4  helped
```

The [baseline](/reference/glossary#baseline) passed 0 of 4 trials and the [variant](/reference/glossary#variant) passed 4 of 4, so the [statistical lift](/reference/glossary#statistical-lift) reads `helped`. The skill ships with evidence behind it. Run the same comparison on each later change, and a drop in lift shows up before users see it.
