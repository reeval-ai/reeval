---
title: "Evaluate"
description: "Declare an evaluation that gives an agent one task and checks the outcome."
---

Declare each evaluation in its own `*.eval.ts` file with `defineEval()`: a task for the agent and the graders that check the outcome. For the definition, see [Evaluation](/reference/glossary#evaluation).

reeval loads every `*.eval.ts` and `*.eval.py` file under the `evals/` folder. The example evaluation adds a feature to `sindresorhus/camelcase`, a real npm package, checked out at a release tag.

## Write the evaluation

<Steps>
<Step title="Name the question">

The eval's id is its file path under the eval root without `.eval.ts`, such as `camelcase/separators`. Results lead with the id, so you know what a pass means before reading any grader. In the `evals/camelcase/separators.eval.ts` file, declare the evaluation:

```ts title="evals/camelcase/separators.eval.ts"
import { defineEnvironment, defineEval, defineGrader } from '{{ pkg }}'
import { hasFile, succeeded } from '{{ pkg }}/graders'
import { docker } from '{{ pkg }}/sandbox'

const camelcase = defineEnvironment('camelcase', ({ git }) => ({
  workspace: git('github:sindresorhus/camelcase', {
    ref: 'v10.0.0',
    init: true,
  }),
}))

const separators = defineGrader('separators-work', ({ file }) => ({
  env: docker(),
  required: true,
  files: ['index.js', 'package.json'],
  data: { test: file('./hidden/separators.test.js') },
  grade: async (c) => {
    await c.sandbox.writeFile('separators.test.js', c.data.test as string)
    const run = await c.sandbox.exec('node --test separators.test.js')
    return run.exitCode === 0
  },
}))

export default defineEval({
  environment: camelcase,
  graders: [
    succeeded('node --test'),
    hasFile('readme.md', /separators/),
    separators,
  ],
  task: async (c) => {
    await c.send(
      'Add a separators option to camelCase: a string of extra characters ' +
        "that also separate words, so camelCase('foo/bar', {separators: '/'}) " +
        "is 'fooBar'. Add tests to test.js and document it in readme.md. " +
        'Run the tests with node --test.',
    )
    await c.exec('node --test')
  },
})
```

A path such as `camelcase/test-2` says nothing about what passed. Moving an eval to another file starts its history again, so settle the id before you record runs.

</Step>
<Step title="Write one prompt">

Ask for the outcome you want in `c.send()`. The graders then decide whether the harness reached it.

Name the files the task is about, such as `test.js` and `readme.md`. Leave out the hidden test: the `separators-work` grader runs `separators.test.js` in a sandbox of its own after the harness finishes, so a pass shows the option works on cases the harness never saw.

</Step>
<Step title="Check the outcome">

Each entry in `graders` is a grader. Its name, such as `separators-work`, names its row in the result. For more information about every kind of assertion, see [Assertions](/evaluations/grading/assertions).

To measure a change, such as a skill, replace `environment` with `compare`. For more information about the baseline, the variant, and the effect, see [Measure lift against a baseline](/results/compare/lift).

</Step>
<Step title="Verify with the `reeval run --dry-run` command">

Plan the run with the `reeval run --dry-run` command:

```bash
npx reeval run --dry-run
```

The `reeval run --dry-run` command plans the run without starting a sandbox or a harness, so it needs no API key. The header counts the evaluations, cells, and trials, and estimates the time:

```text
REEVAL v0.16.1  dry run

  ➜  Run:       20261029T204616Z_e6be7d1_cursor-agent_v23d
  ➜  Harness:   cursor:composer-2.5 (effort: not checked)
  ➜  Sandbox:   docker
  ➜  Scope:     1 eval file · 1 eval · 1 cell · 1 trial
  ➜  Est. Time: ~3m 00s (serial)
```

A table below the header lists each evaluation by its file id. If the evaluation is missing, check that its file ends in `.eval.ts` or `.eval.py` and is in the `evals/` folder.

</Step>
</Steps>

To start the trials, run the same command without `--dry-run`. For the runnable project, see [`with-existing-codebase`](https://github.com/reeval-ai/reeval/tree/main/examples/with-existing-codebase).

## Send the task

The prompt in `c.send()` is what each trial sends to the agent, in a fresh sandbox, after the environment is in place. For the definition, see [Task](/reference/glossary#task).

```ts title="evals/camelcase/separators.eval.ts"
await c.send('Add a separators option to camelCase: …')
```

For more information about a task over several prompts, see [Turns](/evaluations/task/turns).

## Set a timeout

The `timeout` option limits each trial, and it defaults to `'15m'`. The clock starts after the setup commands finish. A trial that reaches the timeout fails. In the `evals/camelcase/separators.eval.ts` file, add `timeout` to the spec:

```ts title="evals/camelcase/separators.eval.ts"
export default defineEval({
  environment: camelcase,
  timeout: '30m',
  task: async (c) => {
    // ...
  },
})
```

For more information about the accepted durations, see [the `timeout` option](/reference/options#timeout).

## Skip an evaluation

`skip: true` or `skip: 'reason'` on `defineEval` keeps the eval in the project without running it; a string reason is listed in the plan. TypeScript eval files have no `.only` or `.todo`. For a runnable project with `skip`, see [`with-skip`](https://github.com/reeval-ai/reeval/tree/main/examples/with-skip).

For more information about sharing options across several evaluations, see [Groups](/evaluations/task/groups).
