description: "Fail the trial when the agent's work misses an assertion."

You list graders in the task's `graders`. A grader that scores below 1 lowers the trial's score. For more information about how an assertion becomes a final state, see [Assertion](/reference/glossary#assertion). For more information about scoring the reply with a model, see [Judgments](/evaluations/grading/judgments).

## Check a file the agent wrote

`hasFile` reads a file in the workspace after the task returns. Its `name` option is the label in the result. The `camelcase` environment is the one from [Evaluate](/evaluations/evaluate).

In the `evals/camelcase.eval.ts` file, send the instruction and check that the readme documents the option:

```ts title="evals/camelcase.eval.ts"
export default defineEval({
  environment: camelcase,
  graders: [hasFile('readme.md', /separators/)],
  task: async (c) => {
    await c.send(
      'Add a separators option to camelCase: a string of extra characters ' +
        "that also separate words, so camelCase('foo/bar', {separators: '/'}) " +
        "is 'fooBar'. Add tests to test.js and document it in readme.md. " +
        'Run the tests with node --test.',
    )
  },
})
```

Without a name, the row reads `has-file:readme.md`. The second argument is a string the file contains or a regular expression it matches:

```ts title="with-checks-and-gates.eval.ts"
hasFile('test/math.test.js', 'divide(', { name: 'tests-divide' }),
```

## Run the project's tests

`c.exec` runs a command in the sandbox and returns `exitCode`, `stdout`, and `stderr`. `succeeded` passes when the last `c.exec` of that command, or with that `label`, exited 0.

In the `evals/camelcase.eval.ts` file, run the repository's tests, and grade a hidden test the prompt never mentions in a sandbox of its own:

```ts title="evals/camelcase.eval.ts"
  graders: [succeeded('node --test'), separators],
  task: async (c) => {
    // ...
    await c.exec('node --test')
  },
```

For the `separators` grader, see [Evaluate](/evaluations/evaluate). For more information about `c.exec`, see [the `c.exec` method](/reference/attempt-context#cexec). For a runnable project, see [`with-existing-codebase`](https://github.com/reeval-ai/reeval/tree/main/examples/with-existing-codebase).

## Check what the agent did

`wrote` checks the paths the agent's write and edit tool calls touched. `ran` checks shell commands the harness ran, and counts them:

```ts title="with-trajectory-matchers.eval.ts"
  graders: [
    wrote('src/math.js'),
    ran(/node --test|npm (test|t)\b/),
    ran(
      { program: 'npm', args: /^(install|i|add)\b/ },
      { name: 'installed-nothing', score: (n) => (n === 0 ? 1 : 0) },
    ),
  ],
```

A string or regular expression matches anywhere in the command line, so `/genkit/` also matches `cat genkit.config.ts`. The `{ program, args }` form matches the program each part of the line ran, after wrappers such as `FOO=1`, `timeout`, and `npx`. For the full list, see [`shellCommands()`](/reference/authoring-api#shellcommands).

`calledTool`, `calledMcp`, and `usedSkill` read the same trajectory. `withinLimits` caps the tokens, tool calls, and time the turns took, as in `withinLimits({ tokens: 20_000, toolCalls: 30 })`. `notInDiff` and `inDiff` read the workspace diff. For a runnable project, see [`with-trajectory-matchers`](https://github.com/reeval-ai/reeval/tree/main/examples/with-trajectory-matchers).

`searched` and `fetched` record an error when the harness does not report web searches or web fetches.

## Use required graders

Every grader reports on each trial. A grader with `required: true` that scores below 1 makes the trial's score 0. In the `evals/camelcase.eval.ts` file, both file graders report on each trial:

```ts title="evals/camelcase.eval.ts"
  graders: [
    hasFile('readme.md', /separators/, { name: 'readme-documents-it' }),
    hasFile('test.js', /separators/, { name: 'tests-cover-it' }),
  ],
```

To stop the task, throw from it: an `EvalError` or a failed `assert` fails the trial, and no grader runs.

## Troubleshooting

Match the trial error to a fix:

| Symptom | Check | Next action |
|---|---|---|
| `has-file:readme.md scored 0.00` | `hasFile` found no file at that path, or it didn't match. | Use the path the prompt names. |
| `succeeded:node --test scored 0.00` | The command's last `c.exec` exited with a code other than 0. | Read its output in the record, then change the command or the task. |
| `the task ran no c.exec labeled or running "node --test"` | The task never ran the command `succeeded` names. | Run it in the task with `c.exec`, or name its `label`. |
| `searched can't check this turn: its harness doesn't report web searches` | The grader threw `HarnessCapabilityError`. | Check the reply or a file, or use a harness that reports web searches. |
