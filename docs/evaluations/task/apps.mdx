---
title: "Check an app"
description: "Capture the app the agent built and judge what it shows."
---

A file assertion can't tell you whether a page renders. The `nextApp` environment must contain the app project before you start. For more information about the `nextApp` environment, see [Environments](/configuration/environments).

Three calls check the app the agent built:

1. Start the app in the sandbox with `c.serve`.
2. Capture a page with `c.capture`.
3. Send the capture to the judge.

## Start a server

`c.serve` starts a command in the background and returns its port. reeval allocates a free port and sets it as `PORT`, so a server that reads `PORT` listens where reeval expects it. In the `evals/sign-in.eval.ts` file, build and start the app:

```ts title="evals/sign-in.eval.ts"
import { defineEval, EvalError } from '{{ pkg }}'
import { judge } from '{{ pkg }}/graders'
import { nextApp } from './environments.ts'

export default defineEval({
  environment: nextApp,
  graders: [
    judge('Does the screenshot show an email field and a password field?', {
      name: 'two-fields',
      inputs: { artifacts: ['login'] },
    }),
  ],
  task: async (c) => {
    await c.send('Add a /login page with email and password fields.')
    const build = await c.exec('npm run build')
    if (build.exitCode !== 0) {
      throw new EvalError({ reason: "the app doesn't build" })
    }
    const app = await c.serve('npm start')
    await c.capture(app, { path: '/login', wait: 'idle' })
  },
})
```

## Check the running app

`c.exec` runs in the sandbox, so a request to `localhost` on the server's port reaches the app. `c.serve` returns once the server listens. In the `evals/sign-in.eval.ts` file, check the page over HTTP:

```ts title="evals/sign-in.eval.ts"
const url = `localhost:${app.port}/login`
await c.exec(`curl -fsS --retry 10 --retry-connrefused ${url}`, {
  label: 'serves /login',
})
```

`-f` makes an HTTP error a non-zero exit code, which fails a `succeeded('serves /login')` grader. To grade the body, record `stdout` from the `c.exec` result with `c.observe`.

## Capture a page

`c.capture` takes a `ServeHandle` or a port and opens a path on it in a headless browser on the host through a tunnel to the sandbox. It waits until the server answers, then saves the image at the `artifacts/<name>.png` path in the trial record. The sandbox image needs no browser, because reeval downloads one into its cache on the first capture.

`path` defaults to `/`. `name` defaults to the path, so `/login` saves `login.png`, and a name can't repeat in one trial. `wait` defaults to `'load'`; use `'idle'` to wait until at most two requests are in flight for 500 ms, or `{ ms: 500 }` to wait a fixed time.

In the `evals/sign-in.eval.ts` file, name a second capture:

```ts title="evals/sign-in.eval.ts"
const error = await c.capture(app, {
  name: 'login-error',
  path: '/login?error=1',
})
```

To interact with the page before the capture, pass `instructions` as goal strings, which a vision model from `capture.model` drives.

## Judge a capture

The `artifacts` input on a `judge()` grader sends captures to the judge as images: their names, or `true` for every capture. An evaluation model such as `typesafe-ai/jev-1.14.0` takes PNG captures, and a provider that can't take files fails the call. Ask what the picture shows, such as a field or a label, not whether it looks good.

In the `evals/sign-in.eval.ts` file, add a grader that sends both captures:

```ts title="evals/sign-in.eval.ts"
judge('Does the error page keep both fields and show one error message?', {
  name: 'error-state',
  inputs: { artifacts: true },
}),
```

For more information about the judge and its model, see [Judgments](/evaluations/grading/judgments).

In a comparison, a question shows each side's own capture when its `artifacts` names the captures, or is `true`, so the model sees the baseline's page beside the variant's. For more information about pairwise questions, see [Ask questions across trials](/evaluations/grading/questions).

## Set the viewport and browser

The viewport defaults to 1280×720. In the `evals/sign-in.eval.ts` file, set the capture width and height:

```ts title="evals/sign-in.eval.ts"
{ environments: nextApp, capture: { viewport: { width: 390, height: 844 } } },
```

`viewport: 'full-page'` captures the whole page. `browser: false` stops reeval from using its browser on the host, and `c.capture` then throws. For more information about every key, see [the `capture` option](/reference/options#capture).
