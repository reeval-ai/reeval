---
title: "Group evaluations"
description: "Apply the same options to several evaluations."
---

When several evaluations share an environment, tags, or the `judge` option, put the shared fields in a helper module and spread them into each `defineEval` call. The two evaluations below ask for Vitest tests in a `plain` environment, defined in the `evals/environments.ts` file.

## Group evaluations

Export shared options from one module. In the `evals/shared.ts` file, give both evaluations the `plain` environment and the `smoke` tag:

```ts title="evals/shared.ts"
import { plain } from './environments.ts'

export const shared = { environment: plain, tags: ['smoke'] as const }
```

Each eval gets its own file and spreads `shared`:

```ts title="evals/shoehorn/build-only-fields.eval.ts"
import { defineEval } from '{{ pkg }}'
import { hasFile } from '{{ pkg }}/graders'
import { shared } from '../shared.ts'

export default defineEval({
  ...shared,
  graders: [hasFile('src/user.test.ts', /fromPartial(<\w+>)?\(/)],
  task: async (c) => {
    await c.send('Add a Vitest test for getUserId in src/user.test.ts.')
  },
})
```

```ts title="evals/shoehorn/mock-services.eval.ts"
import { defineEval } from '{{ pkg }}'
import { hasFile } from '{{ pkg }}/graders'
import { shared } from '../shared.ts'

export default defineEval({
  ...shared,
  graders: [hasFile('src/billing.test.ts', /fromPartial(<\w+>)?\(/)],
  task: async (c) => {
    await c.send('Add a Vitest test for chargeCard in src/billing.test.ts.')
  },
})
```

## Nest groups

A helper can spread another helper and add its own fields. In the `evals/billing-shared.ts` file, add the `billing` tag on top of `shared`:

```ts title="evals/billing-shared.ts"
import { shared } from './shared.ts'

export const billing = { ...shared, tags: [...shared.tags, 'billing'] as const }
```

The billing evaluation spreads `billing` and keeps `shared`'s `plain` environment and `smoke` tag.

## Override an option in one evaluation

An `environment`, `timeout`, `runs`, `target`, or `sandbox` on one `defineEval` call replaces the spread value for that evaluation. The other evaluations keep the shared value. In the `evals/shoehorn/build-only-fields.eval.ts` file, give one evaluation a longer timeout:

```ts title="evals/shoehorn/build-only-fields.eval.ts"
export default defineEval({
  ...shared,
  timeout: '30m',
  task: async (c) => {
    // ...
  },
})
```

## Verify with the `reeval run --dry-run` command

The `reeval run --dry-run` command plans the run without starting a sandbox or a harness, so it needs no API key. Plan the run:

```bash
npx reeval run --dry-run
```

The header counts the evaluations, cells, and attempts, and estimates the time. Each row names an evaluation by its file id. If an evaluation is missing, check that its file ends in `.eval.ts` or `.eval.py` and sits under the `evals/` folder.

## Skip or plan an eval

`skip: true` or `skip: 'reason'` on `defineEval` skips the eval; a string reason is listed in the plan. TypeScript eval files have no `.only` or `.todo`. For a runnable project with `skip`, see [`with-skip`](https://github.com/reeval-ai/reeval/tree/main/examples/with-skip).

## See how options cascade

Options cascade from the config and profile `defaults` to each eval. For the full order, see [The cascade](/reference/options#the-cascade). Tags on the eval add up with profile tags, so `npx reeval run --tag smoke` runs both evaluations above. For more information about filtering by tag, see [Filter evaluations](/evaluations/runs/running#filter-evaluations).
