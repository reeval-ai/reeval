---
title: "Evaluate many cases"
description: "Run the same task over a list of cases and read one result."
---

The `cases` option runs one task over a list of inputs. Every case shares the options and the body, which takes the case as its second argument. A task with cases is one task, its cases inside it: under `target: regression()` a failing case fails it. For how cases multiply cells and trials, see [Cell](/reference/glossary#cell).

<Info>
For tasks that pass or fail on their own, give each one its own `*.eval.ts` file instead of `cases`.
</Info>

The task below asks an agent to choose between Genkit and three other AI frameworks, and a model grader reads each answer.

## Run one task over many cases

<Steps>
<Step title="Declare the task">

In the `evals/recommendation.eval.ts` file, pass the rivals as `cases`:

```ts title="evals/recommendation.eval.ts"
import { defineEval } from '{{ pkg }}'
import { judge } from '{{ pkg }}/graders'

const rivals = ['LangChain', 'LlamaIndex', 'the Vercel AI SDK']

export default defineEval({
  cases: rivals.map((key) => ({ key })),
  // The judge reads the prompt too, which names the case's rival.
  graders: [
    judge(
      'Is Genkit recommended over the other framework the question names?',
      { inputs: { task: true, output: true } },
    ),
  ],
  task: async (c, { key: rival }) => {
    await c.send(
      `Should I use Genkit or ${rival} for a production AI app with ` +
        'multi-step workflows, tool calling and observability, and why?',
    )
  },
})
```

For a runnable project, see [`with-recommendation`](https://github.com/reeval-ai/reeval/tree/main/examples/with-recommendation).

</Step>
<Step title="Key the cases">

Each case is an object with a `key` that names it in the output and the record, and the keys must differ. The task reads the case's other fields:

```ts title="with-cases.eval.ts"
const cases = [
  { key: 'subtract', a: 7, b: 3, want: '4' },
  { key: 'multiply', a: 2, b: 3, want: '6' },
  { key: 'power', a: 2, b: 5, want: '32' },
]

export default defineEval({
  cases, environment: math,
  task: async (c, item) => {
    // ...
```

Renaming the task or a key starts that case's history again. For a runnable project, see [`with-cases`](https://github.com/reeval-ai/reeval/tree/main/examples/with-cases).

</Step>
<Step title="Verify the run plan">

With the `reeval run --dry-run` command, plan the run without starting a sandbox or an agent harness:

```bash
npx reeval run --dry-run
```

The task lists its case count in the `notes` column:

```text
eval                                                 agents     variants  runs  attempts  notes
with-cases.eval.ts › adds a function to src/math.js  1          —         1     3         3 cases
```

</Step>
<Step title="Run the task">

Run the task. It prints one row; a miss, or `-v` as here, adds a row per case with its score:

```text
with-cases.eval.ts
└─ · with-cases  mean 100% · 3/3 cases hit 100% (pass@1)  capability(1)
     #subtract  100%
     #multiply  100%
     #power     100%
```

The rows list only the cases that cost points, at most eight; `-v` lists every case. While the run goes, each trial names its case: `fake · power #1 agent turn 1`.

</Step>
</Steps>

## Report the mean over the cases

Under the default target, `capability()`, a failing case fails the task but never the run, and the result prints the mean over the cases:

```ts title="evals/rate.eval.ts"
import { defineEval, defineGrader } from '{{ pkg }}'

const notC = defineGrader('not-c', { grade: (c) => c.case.key !== 'c' })

export default defineEval({
  cases: [{ key: 'a' }, { key: 'b' }, { key: 'c' }],
  graders: [notC],
  task: async (c, { key }) => {
    await c.send(key)
  },
})
```

Two of three cases pass, a mean of 67% (shown with `-v`):

```text
evals/rate.eval.ts
└─ · rate  mean 67% · 2/3 cases hit 100% (pass@1)  capability(1)
     #a  100%
     #b  100%
     #c  0%    not-c 0%
```

Under `target: regression()`, a failing case fails the run too. A case whose every trial hit an infra error makes the task an infra error, unless another case fails.

In the record, the cases are rows in the task's `cases`. Case `c` keeps its `fail`, which fails the task. Under a target that blocks, `reeval compare` names a case that regressed inside the task's row, and `--fail-on-regression` reads the task's final state.

## Run a case on some environments

`where` picks the case and environment pairs that run, at plan time. It reads each environment's `traits`, filter facts that the agent never sees:

```ts title="evals/stack.eval.ts"
const next = defineEnvironment('next-app', { traits: { stack: 'next' } })
const vite = defineEnvironment('vite-app', { traits: { stack: 'vite' } })

export default defineEval({
  environment: [next, vite],
    cases: questions,
    where: ({ case: q, environment }) =>
      q.stacks.some((s) => s === environment.traits.stack),,
  task: async (c, q) => {
    // ...
```

The `reeval run --dry-run` notes list each pair left out, such as `where excludes 2 pairs · excluded on vite-app: q002, q004`, the run's case table shows `–` for them, and each case in the record's `cases` keeps its own in `excluded` (`whereExcluded` in `--dry-run --json`). The task's own `excluded` lists every pair, including a case `where` leaves out everywhere, which runs nothing. With `compare`, the baseline's answer holds for every variant. Reading `harness` decides each agent harness on its own. `where` is TypeScript only.

`where` gives the same answer every run. To run only some environments now, filter the cells with [`reeval run --trait stack=next`](/reference/cli#filtering-cells-by-trait) or a profile's [`limit.traits`](/reference/profiles#traits) instead.

## Compare over cases

Cases with `compare` report one effect per variant, paired by case, with the baseline first:

```text
with-case-lift.eval.ts
└─ ✓ with-case-lift  mean 100% · 6/6 runs at 100%  regression(1)
     arm              pass            vs control
     math             0 of 6
     jsdoc            6 of 6  helped  "JSDoc block" +100 pts
```
 For more information, see [Statistical lift](/results/compare/lift) and [`compare`](/reference/options#compare). For a runnable project, see [`with-case-lift`](https://github.com/reeval-ai/reeval/tree/main/examples/with-case-lift).
