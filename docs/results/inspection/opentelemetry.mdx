---
title: "Export to OpenTelemetry"
description: "Send the agents' traces, and reeval's own spans, logs, and machine metrics, to an OpenTelemetry backend as the run goes."
---

Set the standard OpenTelemetry variables and `reeval run` sends each trial's agent trace to any OTLP backend while it runs. The same variables with a `REEVAL_` prefix (`REEVAL_OTEL_*`) send reeval's own trace, its log records, and the machine's metrics.

## Send a run to a collector

Point `OTEL_EXPORTER_OTLP_ENDPOINT` at a collector's OTLP/HTTP port and run as usual:

```bash
docker run -d --name jaeger -p 16686:16686 -p 4318:4318 \
  jaegertracing/jaeger:latest
OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318 npx reeval run
```

Open `http://localhost:16686` and pick the `reeval` service. Each trial is one trace: the agent's span, its turns, and their model and tool calls, linked to the trial's span in reeval's own trace. With no endpoint set, reeval loads none of this and sends nothing.

## Send a run to a hosted backend

A hosted backend takes the same variables, with its key in `OTEL_EXPORTER_OTLP_HEADERS`:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://api.honeycomb.io
export OTEL_EXPORTER_OTLP_HEADERS="x-honeycomb-team=$HONEYCOMB_API_KEY"
export OTEL_SERVICE_NAME=evals
npx reeval run
```

Grafana Cloud takes `https://otlp-gateway-<zone>.grafana.net/otlp` with `Authorization=Basic%20<token>`. Datadog takes an Agent's or the OpenTelemetry Collector's OTLP endpoint. URL-encode a header value's spaces and commas as `%20` and `%2C`.

Only reeval's own process exports. No `OTEL_*` or `REEVAL_OTEL_*` variable reaches the sandbox or the agent, and an eval that declares one in `env`, `secret.fromEnv()` or an MCP server's `env` is refused.

## What a run sends

| Signal | What | When |
|---|---|---|
| Traces (`OTEL_*`) | Each trial's agent: `invoke_agent`, each `turn`, and its `chat` model calls and `execute_tool` calls, with GenAI and OpenInference model, token, and cost attributes, and each check and natural-language assertion as a `gen_ai.evaluation.result` event. No prompt, answer, or tool input or output | Each `turn` and its `execute_tool` calls as the turn ends, the rest when the trial ends |
| Traces (`REEVAL_OTEL_*`) | The spans in [`spans.jsonl`](/reference/run-record): the run, each machine, container, trial, lease, and phase | In batches as each span ends; the run's span last |
| Logs (`REEVAL_OTEL_*`) | The run's start, its notices, and one record for each finished trial with its final state, on the run's trace | In batches as they happen |
| Metrics (`REEVAL_OTEL_*`) | `system.cpu.utilization`, `system.cpu.load_average.1m`, `system.memory.usage`, `system.memory.utilization`, `system.filesystem.usage`, and `system.filesystem.utilization` for the project's and staging filesystems (labeled `reeval.filesystem.role`), plus reeval's `process.cpu.utilization` and `process.memory.usage` | Every `REEVAL_OTEL_METRIC_EXPORT_INTERVAL` (60 seconds), and once at the end |

Every span and log record carries `reeval.run.id`, so one query finds a run. A run that stops early leaves the spans that had ended; their parent, the run's span, is missing.

## Choose what to send

Each signal takes its own variables over the shared ones:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318
export REEVAL_OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318
export REEVAL_OTEL_METRICS_EXPORTER=none
export REEVAL_OTEL_EXPORTER_OTLP_LOGS_ENDPOINT=http://logs.internal:4318/v1/logs
export OTEL_RESOURCE_ATTRIBUTES=deployment.environment=ci,team=evals
```

reeval sends OTLP/HTTP as protobuf, or as JSON with `OTEL_EXPORTER_OTLP_PROTOCOL=http/json`; it doesn't send gRPC. Each export reads only its own variables, so the two can go to different backends with different keys. A backend that's down or refuses a batch prints a warning when the run ends, and the run's result and exit code stay the same. For every variable reeval reads, see [Environment variables](/reference/environment-variables#otelexporterotlpendpoint).
