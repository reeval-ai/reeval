---
title: "Compare with past runs"
description: "Prevent regressions by comparing the final states of two recorded runs."
---

`reeval compare` diffs two runs one task at a time and names each one that regressed, was fixed, or can't be compared. It reads the runs you recorded to the history folder ([History](/evaluations/runs/recording)). For more information about the baseline and variants inside one run, see [Measure statistical lift against a baseline](/results/compare/lift).

## Compare two runs

With no arguments, `reeval compare` takes the most recent run as the head and picks the base for you: the newest recorded run at a commit in the head's Git ancestry. When no run is in the ancestry, the base is the previous complete run. Run it after a run finishes:

```bash
npx reeval compare
```

To choose both runs, name the base first and the head second:

```bash
npx reeval compare latest~1 latest
```

A run is `latest`, `latest~N`, a run id or a unique prefix of one, or a Git SHA prefix. `reeval history` lists them.

When no earlier recorded run exists, `reeval compare` says so and lists every task as `new`.

## Read the diff

`reeval compare` prints one block per task that changed and collapses each run of unchanged tasks to `+N same`. A regressed block lists the assertions whose final states changed, and a block that can't be compared names what changed:

```text
can't compare    adds a tested multiply function
  changed          harness config
  base             20261024T145533Z_…  pass
  head             20261024T145534Z_…  fail
  tests pass       failed
    expected command to succeed, exit code 1
  +1 more passed

+1 same

regressed        adds a LangGraph node
  base             20261020T230147Z_958e309_cursor-agent_aamj
  head             20261020T230148Z_958e309_cursor-agent_qghb
  graph compiles   pass → fail
    expected command to succeed, exit code 1
  state schema     not run
  +1 more passed
```

The `can't compare` block comes from [`with-history`](https://github.com/reeval-ai/reeval/tree/main/examples/with-history), whose scripted agent changed between the runs.

Each block and the tally use these words:

| Word | Meaning |
| :--- | :--- |
| `regressed` | The task passed in the base and fails in the head. |
| `fixed` | The task failed in the base and passes in the head. |
| `same` | The final state is the same in both runs, or the target only reports. |
| `can't compare` | The task's source files, environment, agent harness config, image, agent CLI, model grader, agent context, or gateway changed between the runs, so a changed final state has another explanation. The block names what changed. |
| `infra error` | One side ended in an infrastructure error, so it has no final state. |
| `new` | Only the head has the task. |
| `removed` | Only the base has the task. |
| `now fails`, `now passes` | In an older record, a case flipped under a mean-score target that gated its rate over the cases. The task's own row is the verdict. |

When two runs differ only in which cells ran, `reeval compare` compares the cells both have and names the cells only one has. When the runs share no cell, or a shared cell changed, the task reads `can't compare`. It prints `can't compare` for a final state change when one side's only failures are trials an interrupt canceled, or when the served judge model changed. Add `-v` to print every task with each cell's lift, effort and stack changes.

## Compare runs of different cases

When two runs ran different [`cases`](/evaluations/task/cases) of a task, `reeval compare` compares the cases both ran and lists the rest as `new` and `removed`:

```text
can't compare    answers a stack question
  changed          case q4 added
  base             20261101T103232Z_5f71290_cursor-agent_mrtz  pass
  head             20261101T103234Z_5f71290_cursor-agent_s7w4  fail
  cases added      q4
  cases removed    q3
  removed          q3
    base             20261101T103232Z_5f71290_cursor-agent_mrtz  pass
  new              q4
    head             20261101T103234Z_5f71290_cursor-agent_s7w4  fail
    answers it       failed  evals/questions.eval.ts:8
      expected true to be false // Object.is equality
  +2 same
```

`--json` lists them in the row's `caseScope`. A failing case only the head ran makes the task `can't compare`, as above. Under a `minLift`, runs of different cases always read `can't compare`.

## Fail on a regression

To make the diff a gate, add `--fail-on-regression`:

```bash
npx reeval compare --fail-on-regression
```

`reeval compare` exits with code 1 when a task `regressed`, or when a `new` or `can't compare` task fails, since no earlier run passed it, for tasks whose target blocks. Otherwise it exits 0. Add `--md` to write the diff into a [CI](/evaluations/runs/ci) job summary.
