---
title: "Read a run's output"
description: "Read the outcomes, the tally, and the remarks that reeval run and reeval show print."
---

`reeval run` ends with a status list: each evaluation file, one line per evaluation under it, then a tally of the run. `reeval show` prints the full result blocks with their tables.

## Read the outcomes

```text
with-reeval-mcp.eval.ts
└─ ✗ with-reeval-mcp  mean 67% · 0/1 run at 100%  regression(1)
     #1  67%  succeeded:node --test 0%

Done in 2s · 1 eval · 1 below
Browse it: reeval studio · summary .reeval/runs/…/summary.md
```

Each line is an icon, the evaluation's name, its mean score, the number it's judged on and its [`target`](/reference/options#target): `✓` on target and `✗` below it for a target that blocks, `·` for one that only reports (the default, `capability()`) or an infra error, `–` skipped or todo, and `○` canceled. A miss, a throw, a comparison, or remarks add lines under it: a row per run or [case](/evaluations/task/cases) that cost points, with the graders and failed [assertions](/reference/glossary#assertion) behind it, and a table of the arms.

`-v` prints them under every evaluation, with each full message, file excerpt, snapshot, interval and remark. `--ui agent` always adds the rest of each failure's message and its snapshot.

`Done in` gives the run's time, then the tally, which omits zeros, as in `3 evals · 1 on target · 1 below · 1 report only`. A failure outside any evaluation prints first, as `error:`, and counts as a `run error`. `Browse it:` names the studio and the run's `summary.md` file. For more information about the trace of a failed assertion, see [Debug a failing attempt](/results/inspection/debugging).

On a terminal outside CI, unless `--ui` names a mode, the list draws while the run goes and stays up once it ends: ↑ and ↓ move, → opens an evaluation and, on an open one (`→ more`), shows what `-v` adds, enter opens or closes it, ← steps back, escape folds it, and `q` quits, leaving the list in your scrollback.

An open comparison with cases shows its case table live. → shows five, failed and running first, and `7 cases hidden, → to show`; → again shows all.

A spinner turns while reeval waits on a sandbox, an agent turn or a judge. An evaluation gets its `✓` or `✗` once all its runs end; until then a red spinner marks one with a failed run, which the footer counts: `9 of 10 evals done · 1 failing`. Piped output has no spinner. During the run, Ctrl-C cancels it, and so does `q` pressed twice within three seconds. Each attempt's own log lines print only with `--output-logs` (`-v` selects `full`), and then without the interactive list.

## Read remarks

Under an evaluation, `Worth knowing:` names concerns about it, such as a flaky assertion, a slow MCP server start, or too few runs for a difference to hold. reeval's own rules raise them from the run and its history. Each names the file location to change. At most three concerns print, then `+N more remarks (-v)`. To print the rest, each remark's whole sentence and any suggestion, pass `-v`. A concern prints on the run that first raises it; a slow server start, or too few runs, on every run. It also names an assertion that passed only on a retry.

A remark looks like this:

```text
└─ ✓ with-rules-ab  mean 100% · 1/1 run at 100%  regression(1)
     arm              pass
     short-rules      0 of 1
     detailed-rules   1 of 1  helped
     check            short-rules  detailed-rules
     changelog entry  0 of 1       1 of 1
       expected CHANGELOG.md to match /## Unreleased\s+- feat: /
     +1 more passed
     Worth knowing: 1 run per side; set runs: 4 at with-rules-ab.eval.ts to confirm this difference.
```

The control isn't gated, so its failed check doesn't fail the evaluation. With `-v`, the remark prints its whole sentence:

```text
     Worth knowing: The detailed-rules variant passed 1 of 1 run and the control 0 of 1: better by 100 points, but on too few runs for the difference to hold. Fix at with-rules-ab.eval.ts: set runs: 4, where a difference this size would hold.
```

## Show one run

`reeval show` prints the most recent run as result blocks, with each arm's pass counts and a table of assertions per cell:

```bash
npx reeval show
```

Pass a run id for one run, `--md` for its `summary.md` file, or `--json` for the record:

```bash
npx reeval show <run-id>
npx reeval show <run-id> --md
npx reeval show --json
```

For more information about the job summary in a pull request, see [Fail a pull request when results regress](/evaluations/recipes/gate-pull-requests).

For more information about every `reeval show` flag, see [the `reeval show` command](/reference/cli#reeval-show).
