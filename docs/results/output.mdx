---
title: "Read a run's output"
description: "Read the outcomes, the tally, and the remarks that reeval run and reeval show print."
---

`reeval run` ends with the run's results: a line of facts, a block per evaluation, then a tally. They are the same sections, in the same order, as the run's `summary.md` file and the studio; the terminal prints the shorter subset.

## Read the outcomes

```text
adds a tested multiply function
0 of 1 counted attempt passed · 2s wall time · tokens not reported · cost not reported · reeval@45620f2 (dirty)

FAIL           adds a tested multiply function
               0% passed · 0 of 1 attempt
               failed check, 1 of 1: toSucceed node --test
                 expected command to succeed, exit code 1
                 at with-reeval-mcp.eval.ts:13

Evals: 1 fail

Browse it: reeval studio · summary .reeval/runs/…/summary.md
```

Each block starts with the verdict and the evaluation's name: `PASS`, `FAIL`, `NOT GATED` (no cell is gated, as under [`gate: 'observe'`](/reference/options#gate)), `INFRA ERROR`, `CANCELED`, `SKIPPED` or `TODO`. Under it come the pass rate with `k of n attempts`, how each harness did, the arms of a comparison, and each failed [assertion](/reference/glossary#assertion) with how many attempts it failed, the arm or harness it failed on, its first message line and its location. Infra errors and canceled attempts are counted beside the rate, not in it.

`-v` adds each full message, file excerpt and interval, and each suggestion. `--ui agent` always adds them.

The facts line gives how many counted attempts passed, the run's time, its tokens and its cost. `Evals:` is the tally, which omits zeros, as in `2 fail · 1 pass · 1 infra error`. A failure outside any evaluation prints first, as `Error:`, and counts as a `run error`. `Browse it:` names the studio and the run's `summary.md` file. For more information about the trace of a failed assertion, see [Debug a failing attempt](/results/inspection/debugging).

On a terminal outside CI, unless `--ui` names a mode, a list draws while the run goes: ↑ and ↓ move, → opens an evaluation and, on an open one (`→ more`), shows what `-v` adds, enter opens or closes it, ← steps back, escape folds it, and `q` quits. Once the run ends, the results print in its place.

An open evaluation with cases shows its case table live. → shows five, failed and running first, and `7 cases hidden, → to show`; → again shows all.

A spinner turns while reeval waits on a sandbox, an agent turn or a judge. An evaluation gets its `✓` or `✗` once all its runs end; until then a red spinner marks one with a failed run, which the footer counts: `9 of 10 evals done · 1 failing`. Piped output has no spinner. During the run, Ctrl-C cancels it, and so does `q` pressed twice within three seconds. Each attempt's own log lines print only with `--output-logs` (`-v` selects `full`), and then without the interactive list.

## Read remarks

Under an evaluation, `Next:` names the edit a remark asks for and where, and each `(concern)` line names a concern about the evaluation, such as a flaky assertion, a slow MCP server start, or too few runs for a difference to hold. reeval's own rules raise them from the run and its history. At most three concerns print, then `+N more remarks (-v)`. To print the rest and any suggestion, pass `-v`. A concern prints on the run that first raises it; a slow server start, or too few runs, on every run. A `(note)` line names an assertion that passed only on a retry.

A remark looks like this:

```text
PASS           records the change in the changelog
               short-rules 0% vs detailed-rules 100%: too few runs · 0 of 1 vs 1 of 1 attempt
               short-rules     0%    0 of 1  baseline
               detailed-rules  100%  1 of 1  too few runs
               failed check, 1 of 2, all on short-rules, not gated: changelog entry
                 expected CHANGELOG.md to match /## Unreleased\s+- feat: /
                 at with-rules-ab.eval.ts:20
               Next: at with-rules-ab.eval.ts:14, set runs: 4, where a difference this size would hold
               (concern) The detailed-rules variant passed 1 of 1 run and the control 0 of 1: better by 100 points, but on too few runs for the difference to hold.
```

A control that isn't gated fails as `not gated`. With `-v`, the block adds the difference's interval:

```text
               detailed-rules +100 pts (95% CI -12 pts to +100 pts)
```

## Show one run

`reeval show` prints the most recent run's results, as `reeval run` ends with them:

```bash
npx reeval show
```

Pass a run id for one run, `--md` for its `summary.md` file, or `--json` for the record:

```bash
npx reeval show <run-id>
npx reeval show <run-id> --md
npx reeval show --json
```

For more information about the job summary in a pull request, see [Fail a pull request when results regress](/evaluations/recipes/gate-pull-requests).

For more information about every `reeval show` flag, see [the `reeval show` command](/reference/cli#reeval-show).
