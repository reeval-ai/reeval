---
title: "Test a CLI"
description: "See whether an agent harness runs a CLI and its result works."
---

You test a CLI by installing it on the sandbox image, giving the agent harness an instruction that uses it, and checking the result. The sample uses `jq`. For a runnable project, see [`with-docker-install`](https://github.com/reeval-ai/reeval/tree/main/examples/with-docker-install).

## Install and check the CLI

<Steps>
<Step title="Add the CLI to the image">

In the `evals/cli.eval.ts` file, define an environment that installs the CLI on the sandbox image and copies in the files the agent harness starts from:

```ts title="evals/cli.eval.ts"
import { defineEnvironment, defineEval, EvalError } from '{{ pkg }}'
import { observed } from '{{ pkg }}/graders'
import { docker } from '{{ pkg }}/sandbox'

// jq is baked onto reeval's image once, and the image is cached by the
// exact command list.
const withJq = defineEnvironment('jq', ({ directory }) => ({
  files: directory('./project'),
  sandbox: docker({
    install: [
      'apt-get update && apt-get install -y --no-install-recommends jq' +
        ' && rm -rf /var/lib/apt/lists/*',
    ],
  }),
}))
```

Before any trial starts, reeval builds this `install` layer on the sandbox image if it is missing, so every trial has the CLI. For more information about adding a tool to the image, see [Add toolchains](/configuration/environments/toolchains).

The `project/orders.json` file has five orders, and two of them have a total over 100.

</Step>
<Step title="Write the instruction and the assertions">

In the `evals/cli.eval.ts` file, write the instruction that uses the CLI and check its result:

```ts title="evals/cli.eval.ts"
export default defineEval({
  environment: withJq,
  graders: [observed('count', (out) => out === '2')],
  task: async (c) => {
    await c.send(
      'Write count.sh, a bash script that prints how many orders in ' +
        'orders.json have a total over 100, using jq.',
    )

    if ((await c.exec('jq --version')).exitCode !== 0) {
      throw new EvalError({ reason: 'the image has no jq' })
    }
    c.observe('count', (await c.exec('bash count.sh')).stdout.trim())
  },
})
```

`c.exec` runs a command in the sandbox after `c.send` returns. The task confirms the image has `jq`, and throws an `EvalError`, which fails the trial, when it doesn't. The task observes what the agent harness's script prints, and the `observed` grader compares it with the expected count. For more information about `c.exec` and graders, see [Assertions](/evaluations/grading/assertions).

To check the commands the agent harness ran during the turn, use the `ran` grader. For more information, see [Check what the agent did](/evaluations/grading/assertions#check-what-the-agent-did).

</Step>
<Step title="Run the task">

From the project root, run the task in the `evals/cli.eval.ts` file. The command uses the agent harness named in the `reeval.config.ts` file:

```bash
npx reeval run cli
```

When the `observed` grader passes, the task scores 100%, and its block lists the observed `count`. For more information about the final states and the tally, see [Read a run's output](/results/output).

</Step>
<Step title="Check the install layer">

List the sandbox images with `reeval image build --dry-run`. The install layer sits on top of the agent harness's image. This capture is from after the first run built it:

```text
images  1 sandbox image (nothing built: --dry-run)
docker+0ab0e263 · cursor + install · 1 eval
  ✓ base               reeval-sandbox:cursor-0.1.9  (ready: built (3fa1c0ba62b4))
  ✓ install 1 command  reeval-install:1d7d61958ab1a130  (ready: built (15642b46f47f))
```

Any edit to the command list builds a new layer. Install commands never see secrets or the workspace; put per-trial steps in the environment's `setup`. For more information, see [Run setup commands](/configuration/environments/setup-commands).

</Step>
</Steps>
