## `profiles`

`profiles` in the `reeval.config.ts` file maps a name to `defaults`, `limit`, `judge`, `budget`, `record`, `tags`, `gateway`, `history`, and `cloud`. reeval exits with code 2 for an unknown key or a value of the wrong shape.

```ts title="reeval.config.ts"
import { defineConfig } from '{{ pkg }}'

export default defineConfig({
  profiles: {
    nightly: {
      defaults: { trials: 3 },
      limit: { trials: 1, compare: false },
      judge: { model: 'typesafe-ai/jev-1.14.0' },
      budget: { trials: 80, duration: '2h' },
      record: 'always',
      tags: ['nightly'],
    },
  },
})
```

<Property name="profiles" type="Record<string, Profile>" optional>
  Named profile objects.
</Property>

reeval applies the `reeval.config.ts` file, then `defaults`, then each eval, then `limit`. `defaults.judge` wins over the profile `judge` in that `defaults` step. `--trials` then replaces `trials`.

For more information about the per-key cascade, see [The cascade](/reference/options#the-cascade).

For more information about sizing a run with a profile, see [Size runs with profiles](/evaluations/runs/profiles).

## `defaults`

`defaults` applies before each eval. `defaults.agents` replaces the eval's own `agents` unless the eval sets `pin: ['agents']`; the plan notes `agents set by the eval` when the eval keeps its own list. A later `agents` on the eval can replace or edit `defaults.agents`.

<Property name="defaults" type="ProfileDefaults" optional>
  `agents`, `sandbox`, `environments`, `trials`, `target`, `env`, `egress`, `judge`, `capture`, `question`, and `timeout`.
</Property>

For more information about those keys, see [Options reference](/reference/options).

## `limit`

`limit` narrows `trials`, `compare`, `agents`, and the cells by `traits` after the eval. `pin` on the eval names keys that stay as resolved.

<Property name="limit" type="ProfileLimit" optional>
  The plan notes a cut, as in `trials 3 → 1 (profile nightly)`. It notes protected keys that `limit` also sets, as in `pinned: compare, trials`.
</Property>

For more information about `pin`, see [Options reference](/reference/options#pin).

### `trials`

<Property name="trials" type="number" optional>
  A whole number of at least 1. reeval lowers `trials` only when the resolved value is higher, and turns a `{ bestOf: n }` with `n` above it into this fixed count. `--trials` replaces `trials` after the cap, including when `pin` lists `trials`.
</Property>

### `compare`

<Property name="compare" type="false | { maxVariants: number }" optional>
  `false` drops the variants and runs the baseline. `{ maxVariants: n }` keeps the first `n` variants. `n` is a whole number of at least 0.
</Property>

`limit.compare` applies when the resolved evaluation has `compare`, whether a group, a profile's `defaults`, the config or the evaluation set it. After `false` or `{ maxVariants: 0 }`, the baseline gates like an evaluation without `compare`. The plan notes `compare off (profile nightly)` or `variants 4 → 1 (profile nightly)`.

A pairwise question needs two trials that differ in a factor it varies. When the limit leaves none of its factors varying, the plan notes `1 pairwise question off (profile nightly)`, or `2 pairwise questions off (profile nightly)` for two. When it leaves some, the question keeps those and the plan notes `1 pairwise question narrowed (profile nightly)`, or `2 pairwise questions narrowed (profile nightly)` for two.

### `agents`

<Property name="agents" type="string[]" optional>
  Harness ids to keep. A default id includes `[effort=<value>]` whenever `effort` is set, and a tag for each shared option set. reeval skips an evaluation left with none.
</Property>

The plan notes `agents 2 → 1 (profile nightly)`. A miss notes `skipped: no agent left: profile nightly allows none`, with the allowed ids in place of `none`.

reeval exits with code 2 for anything but a list of id strings. Descriptors belong on `defaults.agents`.

### `traits`

```ts
profiles: {
  next: { limit: { traits: { stack: ['next', 'remix'], auth: 'clerk' } } },
}
```

<Property name="traits" type="Record<string, string | string[]>" optional>
  The cells to keep, by their environment's traits. A cell matches a key when its trait is the value, or one of a list's, or a list trait contains it. Every key must match. With `compare`, a cell goes by its baseline's traits, so every variant runs with its baseline or not at all.
</Property>

`limit.traits` applies after `where`, together with [`--trait`](/reference/cli#filtering-cells-by-trait), and `pin` doesn't protect from it. The plan notes `profiles.next.limit.traits.stack leaves out vite-app`. An evaluation, or a case, left with no cell is skipped: `no cell left: profiles.next.limit.traits.stack matches none of vite-app`.

reeval exits with code 2 for a value that isn't a string or a non-empty list of strings, and for a key that no baseline environment of the selected evaluations defines, with the closest key it does define.

## `judge`

`defaults.judge` wins field by field over the profile `judge`, and that result wins over the config `judge`. The eval merges over that result.

<Property name="judge" type="ConfigJudgeOptions" optional>
  The same fields as `defaults.judge`.
</Property>

For more information about judge fields, see [Options reference](/reference/options#judge).

## `budget`

`budget` merges key by key over the config `budget`. A set key replaces the config value. An omitted key keeps it.

<Property name="budget" type="{ trials?: number, duration?: Duration }" optional>
  reeval exits with code 2 for `usd`, `tokens`, or any other key.
</Property>

### `trials`

<Property name="trials" type="number" optional>
  A whole number of at least 1. reeval exits with code 2 before the run starts when the plan is over the cap, unless `--force` is set. The header's `Scope:` line shows the cap, as in `(budget: 5 ✗)`.
</Property>

### `duration`

<Property name="duration" type="Duration" optional>
  Greater than zero. A number is milliseconds, and a number plus `ms`, `s`, `m`, or `h` is that unit.
</Property>

The header's `Scope:` line appends the duration, as in `(budget: 5 ✗, 2h)`.

The timer starts when the first trial starts. At the cap, running trials finish and queued trials are skipped. The record status is `budget`, and the run fails.

## `record`

`record` replaces the config `record`. An omitted `record` keeps the config value, whose default is `ci`.

<Property name="record" type="'manual' | 'ci' | 'always'" optional>
  Same values as [`record`](/reference/options#record).
</Property>

reeval exits with code 2 for any other `record` value.

`--record` copies the run when `reeval run` ends. An interrupted run is not copied. A run that stops with status `budget` is copied.

For more information about copying a run later, see [reeval record](/reference/cli#reeval-record).

## `cloud`

`cloud` replaces the config [`cloud`](/reference/options#cloud). `--cloud` and `--local` take precedence.

<Property name="cloud" type="boolean" optional>
  Same values as [`cloud`](/reference/options#cloud).
</Property>

## `tags`

`tags` selects evaluations. Every profile filter must hold, and every `--tag` flag must hold.

<Property name="tags" type="string[]" optional>
  Tag filters for this profile, same shape as [`tags`](/reference/options#tags) / `--tag`. reeval omits an evaluation that fails a filter.
</Property>

reeval exits with code 2 when `tags` is not a list of strings.

For more information about tags on a group or evaluation, see [Options reference](/reference/options#tags).

## `gateway`

`gateway` replaces the config's `gateway` list while the profile is selected.

<Property name="gateway" type="GatewayDescriptor[]" optional>
  The same helpers as the config's [`gateway`](/reference/options#gateway), in order of preference.
</Property>

## `provider`

<Property name="provider" type="BoatProviderDescriptor | DaytonaProviderDescriptor" optional>
  Replaces the config [`provider`](/reference/options#provider).
</Property>

## `defaultProfile`

`reeval run` and `reeval image build` read `--profile`, then `REEVAL_PROFILE`, then `defaultProfile`.

<Property name="defaultProfile" type="{ ci?: string, local?: string, cloud?: string }" optional>
  `cloud` applies when `--cloud` or the config's `cloud` sends the run to the cloud, and wins over `ci` and `local`; it can't name a profile whose `cloud` is `false`. `ci` applies when `CI` is set to anything but `false`. `local` applies when `CI` is unset or `false`. An unset matching field selects no profile.
</Property>

A `defaultProfile` name that is not a profile exits with code 2 when the config loads.

An unknown `--profile` or `REEVAL_PROFILE` name exits with code 2. The message lists the names in `profiles`, or says that the `reeval.config.ts` file defines none.

The header's `Profile:` line names it, with the reason unless `--profile` chose it, as in `nightly (REEVAL_PROFILE)`, `pr (auto: CI is set)`, or `pr (default)`. With no profile, that line is absent.

The `profile` field on the config callback is the `--profile` or `REEVAL_PROFILE` name. `defaultProfile` leaves that field unset.

For more information about the `profile` field, see [Configuration reference](/reference/configuration#profile).

For more information about the `--profile` flag, see [reeval run](/reference/cli#reeval-run).
