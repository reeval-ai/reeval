## `defineEval()`

`defineEval(spec)` declares one evaluation. Each `*.eval.ts` file holds exactly one eval and exports it as the default:

```ts title="evals/shoehorn/build-only-fields.eval.ts"
import { defineEval, expect } from '{{ pkg }}'
import { plain, shared } from './shared.ts'

export default defineEval({
  ...shared,
  task: async (c) => {
    await c.send('Add a Vitest test for getUserId in src/user.test.ts.')
    await expect(c, 'uses fromPartial').toHaveFile(
      'src/user.test.ts',
      /fromPartial(<\w+>)?\(/,
    )
  },
})
```

The eval's id is its file path under the eval root without `.eval.ts`, such as `shoehorn/build-only-fields`. Results and history list that id first.

<Property name="spec" type="EvalOptions & { task: EvalFn | CaseFn<T> }" required>
  A plain object of eval options plus `task`, the body called once per attempt. With `cases`, `task` is `(c, item) => Promise<void>`. `environments` is not accepted; use `environment`, one environment or a list.
</Property>

`skip: true` or `skip: 'reason'` declares without running; the plan lists a string reason. TypeScript eval files have no `.only` or `.todo`.

reeval refuses, with exit code 2, no default export, a default export that is not a `defineEval` result, more than one `defineEval` call in one file, a missing `task`, `skip` that is not `true`, `false`, or a non-empty string, `environments` on the eval, `where` without `cases`, and two eval files whose ids differ only in a masked secret.

For more information about `EvalOptions` and the type of each key, see [Options reference](/reference/options).

## Cases

`cases` runs one evaluation over a list of inputs, and `task` receives each as its second argument:

```ts title="evals/shoehorn/handlers.eval.ts"
import { defineEval, expect } from '{{ pkg }}'
import { plain, withShoehorn } from './shared.ts'

const handlers = [
  { key: 'getUserId' },
  { key: 'getUserEmail' },
  { key: 'getUserRole' },
]

export default defineEval({
  cases: handlers,
  compare: { control: plain, variants: [withShoehorn] },
  async task(c, { key: handler }) {
    // ...
  },
})
```

<Property name="cases" type="readonly Case<T>[]" required>
  The inputs, each a JSON object with a `key`; `Case<T>` is `{ key: string } & T`. The cases pool into one pass rate and, under `compare`, one lift paired by case and gated by `compare.minLift`. Each case's data is part of its fingerprint, recorded as a sha256 of its JSON with secrets in its strings masked, so a rotated secret leaves the case the same evaluation. A secret held as a number, or a value under 8 characters in a secret-named variable that no `secret()` reads, is hashed as written: anyone who reads the history could confirm a guess at it.
</Property>

<Property name="cases[].key" type="string" required>
  Each case's key, 1 to 80 characters with no surrounding whitespace, `#`, `›` or control characters; a `/` is fine.
</Property>

<Property name="where" type="Where<T>" optional>
  TypeScript only. Which case and environment pairs run, from each environment's `traits`. For more information, see [the `cases` option](/reference/options#cases).
</Property>

<Property name="task" type="CaseFn<T>" required>
  The body, `(c: AttemptContext, item: Case<T>) => Promise<void>`, called once per attempt with its case.
</Property>

Results print the evaluation's id as a heading and a row per case key. reeval refuses, with exit code 2, a `cases` value that is not a non-empty list, a case that is not an object with a valid `key`, two cases with one key, including two whose keys differ only in a masked secret, `where` without `cases`, and `runs: { bestOf }` beside `cases`. `cases` and `where` are options of `defineEval()` only, not of the config.

For more information about the `all cases` row, see [`compare`](/reference/options#compare).

## Observing without a gate

`gate: 'observe'` declares an evaluation that records what its attempts do and gates nothing:

```ts title="evals/database.eval.ts"
import { defineEval } from '{{ pkg }}'

export default defineEval({
  gate: 'observe',
  runs: 3,
  task: async (c) => {
    await c.send('Add persistence to the app.')
    c.observe('package.json', await c.readFile('package.json'))
  },
})
```

Every cell prints `ran` rather than a pass or a fail, and only run and infra errors fail the run. A failed `expect` reads as a check that failed. reeval refuses, with exit code 2, `compare.minLift` and `runs: { bestOf }` beside `gate: 'observe'`. To keep a compare's cells from gating, set `compare.gate: 'observe'`. For more information, see [`gate`](/reference/options#gate).

## `EvalFn`

`EvalFn` is the type of `task` without `cases`: `(c: AttemptContext) => Promise<void>`. The attempt fails when it throws, rejects, or leaves a failed `expect`.

For more information about `AttemptContext` and the types the methods of `c` take and return, see [Attempt context reference](/reference/attempt-context).

## `defineEnvironment()`

`defineEnvironment(name, spec)` defines what an evaluation runs in. The following declaration extends a control into a variant:

```ts title="evals/environments.ts"
export const plain = defineEnvironment('plain', {
  // ...
})

export const withShoehorn = plain.extend('with-shoehorn', ({ skill }) => ({
  // ...
}))
```

<Property name="name" type="string" required>
  The environment's name, which names its cells. It starts with a letter or digit and continues with letters, digits, `.`, `_`, `@`, `+`, or `-`.
</Property>

<Property name="spec" type="EnvironmentInput" required>
  An `EnvironmentSpec` object, or a callback that receives `EnvironmentHelpers` and returns one synchronously, once, when the file loads. The documented helpers are `secret`, `skill`, `mcp`, `plugin`, `file`, `directory`, and `git`.
</Property>

Relative paths in `spec` resolve against the file that calls `defineEnvironment()`. A spec that omits `sandbox` runs in the cascaded `sandbox` option, else in the default sandbox. reeval refuses, with exit code 2, any other name and a callback that returns a `Promise`. For more information about the default sandbox, see [Sandboxes](/configuration/sandboxes).

The returned `Environment` is a frozen object with the following fields.

<Property name="kind" type="'environment'" required>
  Identifies an environment.
</Property>

<Property name="name" type="string" required>
  The name passed to `defineEnvironment()` or `extendEnvironment()`.
</Property>

<Property name="layers" type="readonly EnvironmentLayer[]" required>
  Each layer's `name` and its `spec` as that layer wrote it, root first.
</Property>

<Property name="extendEnvironment" type="(name: string, spec: EnvironmentInput) => Environment" required>
  Returns a child environment layered on this one.
</Property>

<Property name="extend" type="(name: string, spec: EnvironmentInput) => Environment" required>
  An alias of `extendEnvironment()`.
</Property>

For more information about `EnvironmentSpec`, `EnvironmentHelpers`, each field's type, and how `extendEnvironment()` merges each field, see [Environment fields](/reference/environment-helpers#environmentspec) and [extend](/reference/environment-helpers#extend).

## `defineConfig()`

`defineConfig(config)` returns its argument unchanged, so `reeval.config.ts` is type-checked. For more information about the config keys and the callback form, see [Configuration reference](/reference/configuration#defineconfig).

## `expect()`

`expect(actual, label?)` checks `actual` and records an assertion. For more information about its matchers, `expect.require()`, and `expect.poll()`, see [Matchers reference](/reference/matchers#expect).

## `shellCommands()`

`shellCommands(subject)` returns the programs the agent ran from its shell calls, the tool calls named `bash` or `shell`, in order. The subject is a turn from `c.send()`, a list of turns such as `c.turns`, or `c`.

```ts title="evals/adoption.eval.ts"
import { defineEval, shellCommands } from '{{ pkg }}'
// ...
  const runs = shellCommands(c).filter((r) => r.program === 'genkit')
  c.observe('genkit runs', runs.length)
```

Each command line gives one entry per segment, read the way [`toHaveRun()`](/reference/matchers#tohaverun) reads it: `cd app && npx genkit flow:run x` gives `cd` with `['app']`, then `genkit` with `['flow:run', 'x']`. Each entry is a `ShellCommand`:

<Property name="program" type="string" required>
  The program's name without its directory, after env assignments and wrappers. A package runner's package drops its version.
</Property>

<Property name="args" type="string[]" required>
  The words after the program, with quotes removed.
</Property>

<Property name="line" type="string" required>
  The shell call's whole command line.
</Property>

<Property name="ok" type="boolean | null" required>
  Whether the shell call succeeded, or `null` when the harness never reported its result. It's the whole call's result, not the program's, so every segment of one line has the same `ok`: in `cd missing && genkit start`, `genkit` has `ok: false` though it never ran.
</Property>

<Property name="turn" type="number" required>
  The turn's index in the subject. For a single turn, it's `0`.
</Property>

## `DEFAULT_EGRESS_ALLOW`

`DEFAULT_EGRESS_ALLOW` is a `readonly string[]` of the package registries and GitHub: `registry.npmjs.org`, `registry.yarnpkg.com`, `github.com`, `*.github.com`, `*.githubusercontent.com`, `pypi.org`, and `files.pythonhosted.org`. Spread it into an `egress.allow` list that still installs packages, as in `egress: { allow: [...DEFAULT_EGRESS_ALLOW, 'example.com'] }`.

For more information about egress policies, see [`egress`](/reference/options#egress).

## `DEFAULT_DIRECTORY_IGNORES`

`DEFAULT_DIRECTORY_IGNORES` is a `readonly string[]` of the `glob` patterns `directory()` skips unless `defaultIgnores` is `false`. For more information about `directory()`, see [Environment fields](/reference/environment-helpers#directory).

## `DEFAULT_SKILL_EXCLUDE`

`DEFAULT_SKILL_EXCLUDE` is a `readonly string[]` of the path patterns each skill leaves out unless `exclude` replaces them: `/evals/`, `.history/`, and `*.eval.ts`. For more information about skills, see [Environment fields](/reference/environment-helpers#skilllocal).

## `HarnessCapabilityError`

`HarnessCapabilityError` is the error `toHaveSearched()` and `toHaveFetched()` throw when the turn's `unreported` list holds `web-search` or `web-fetch`. The following assertion catches it:

```ts title="evals/search.eval.ts"
import { defineEval, expect, HarnessCapabilityError } from '{{ pkg }}'
// ...
  try {
    expect(turn, 'searched the web').toHaveSearched(/ai sdk/i)
  } catch (error) {
    if (!(error instanceof HarnessCapabilityError)) throw error
    expect(turn.text, 'names a version').toMatch(/\d+\.\d+/)
  }
```

<Property name="name" type="'HarnessCapabilityError'" required>
  The error's `name`.
</Property>

<Property name="message" type="string" required>
  Names the matcher, the event type, and the alternatives.
</Property>

Uncaught, it fails the attempt, and the record lists the assertion with status `error` rather than `fail`. With `expect()`, the attempt still fails at its end.

For more information about the two matchers, see [Matchers reference](/reference/matchers#tohavesearched).

For more information about `RunRecord` and the assertion's record, see [Run record reference](/reference/run-record).
