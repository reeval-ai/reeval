reeval runs a coding agent in a sandbox and checks the final state. Here you run the same harness as a baseline without the skill and a variant with the skill, then see whether the skill helped.

## Get started

Initialize a suite in your repo, run your first trials, and inspect the results in Studio:

```bash
npx reeval init
npx reeval run
npx reeval studio
```

If you want your coding agent to write the first task for you, paste this into your session:

```text
Add a reeval evaluation suite to this repository:
1. Run `npx reeval init` to scaffold the config and eval directory.
2. Create an environment in `evals/environments.ts` pointing to our starter app or minimal fixture.
3. Write one task in `evals/` that tests a core user workflow end to end using our SDK/CLI/API, with a deterministic grader (`succeeded(...)`) and a binary `judge(...)` check.
4. Run `npx reeval run` and summarize the baseline pass rate and any failure patterns.
```

A coding agent can also follow the [setup skill](https://github.com/reeval-ai/reeval/tree/main/skills/setup).

## Or set up by hand

This example uses Docker for its sandbox. You need these:

| You need | For |
|---|---|
| Node {{ node }} or later | reeval's CLI |
| Docker or Podman | the sandbox |
| An API key for the agent harness | the harness |
| A Google API key (optional) | `reeval analyze`, the model's explanation of a run |

For more information about other harnesses and their keys, see [Harnesses](/configuration/agents).

For more information about Podman or Docker on macOS or Windows, see [Sandboxes](/configuration/sandboxes).

## 1. Set up reeval

Install reeval in the project:

```bash
npm install -D {{ pkg }}
```

Create the project files for the harness:

```bash
npx reeval init --agent claude-code
```

The command writes the `reeval.config.ts` file, an example task in `evals/greet.eval.ts`, and its environment in `evals/environments.ts`. It also adds an `eval` script and the `{{ pkg }}` devDependency to `package.json`, `.env*` and `.reeval/` to `.gitignore`, and a `tsconfig.json`. Add the keys to the `.env.local` file next to the `reeval.config.ts` file. `reeval doctor` names any key that's missing. The Google key is for `reeval analyze`. A run without it still runs the task:

```bash title=".env.local"
ANTHROPIC_API_KEY=replace-with-anthropic-key
GOOGLE_GENERATIVE_AI_API_KEY=replace-with-google-key
```

Claude Code also accepts `CLAUDE_CODE_OAUTH_TOKEN` in place of the Anthropic key.

Build the image the harness runs in:

```bash
npx reeval image build
```

For more information about image builds, see [Toolchains](/configuration/environments/toolchains).

Check Node, Docker, the image, and the keys with the `reeval doctor` command:

```bash
npx reeval doctor
```

The command highlights any environment issues. When it finds none, the output ends with this line:

```text
No problems.
```

Without the Google key, the output ends with this line instead, and you can continue:

```text
No problems, 1 warning.
```

## 2. Write the task

Without the skill, the page is unstyled. Create the `evals/project/index.html` file:

```html title="evals/project/index.html"
<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8" />
    <title>Release notes</title>
  </head>
  <body>
    <h1>Release notes</h1>
    <p>Version 2.0 is out, with faster builds and a new command line.</p>
  </body>
</html>
```

The variant adds Anthropic's `brand-guidelines` skill. Add the baseline and the variant to the end of the `evals/environments.ts` file:

```ts title="evals/environments.ts"
export const page = defineEnvironment('page', ({ directory }) => ({
  files: directory('./project'),
}))

export const withSkill = page.extendEnvironment(
  'brand-guidelines',
  ({ skill }) => ({
    skills: [
      skill.git('github:anthropics/skills', {
        ref: 'dbd4588f9e1033efb41dad4bef2f7947c8993d44',
        path: 'skills',
        only: ['brand-guidelines'],
      }),
    ],
  }),
)
```

Create the task:

```ts title="evals/brand.eval.ts"
import { defineEval } from '{{ pkg }}'
import { hasFile } from '{{ pkg }}/graders'
import { page, withSkill } from './environments.ts'

export default defineEval({
  compare: { control: page, variants: [withSkill] },
  runs: 4,
  graders: [
    hasFile('index.html', /href="styles\.css"/, {
      name: 'links-styles-css',
    }),
    hasFile('styles.css', /#d97757/i, { name: 'brand-orange' }),
    hasFile('styles.css', /Poppins[\s\S]*Lora|Lora[\s\S]*Poppins/, {
      name: 'brand-fonts',
    }),
  ],
  task: async (c) => {
    await c.send(
      "Give index.html Anthropic's look: write styles.css with Anthropic's " +
        'brand colors and fonts, and link it from index.html.',
    )
  },
})
```

The prompt doesn't name the brand's color or fonts, so the graders pass only when the harness knows them. The variant passes when one of its 4 trials passes, under the default target, `capability()`. For more information about why this task uses four trials, see [Statistics](/reference/statistics#too-few-runs).

## 3. Run the comparison

Run the eight trials:

```bash
npx reeval run brand
```

The run prints a block like this one:

```text
  arm               pass  vs control
  page              0 of 4
  brand-guidelines  4 of 4  helped  "brand-orange" +100 pts
  check             page    brand-guidelines
  brand-orange      0 of 4  4 of 4
  brand-fonts       0 of 4  4 of 4
```

The variant passed in 4 of 4 trials and the baseline in 0 of 4, so the effect reads `helped`. Your counts can differ, and the table lists each check that told the arms apart.
